# Amazon Simple Storage Service (S3)

**Category:** Storage  **Level:** 🟢 Beginner
**Last checked against AWS docs:** 2026-11-24 (first draft – needs a human check)

## In one sentence

S3 stores any number of files in the cloud, keeps them safe, and lets you get them back from anywhere over the internet.

## Real-life comparison

S3 is like a huge self-storage warehouse. You rent a unit (a **bucket**), put boxes in it (your **files**), and stick a label on each box (its **key**, or name). The warehouse never runs out of space, it keeps copies of your boxes in several buildings, and you only pay for the space you use.

## What problem does it solve?

Before S3, if a company wanted to store files, it had to buy hard drives and servers, guess how much space it would need, and replace drives when they broke. If the building flooded, the files could be lost.

With S3:
- You never run out of space.
- AWS copies your files across several data centres automatically, so a single failure doesn't lose them.
- You can reach your files from a website, an app or a script anywhere in the world.

## Key words to know

| Word | What it means in plain English |
|------|-------------------------------|
| **Bucket** | A container for your files. Like a storage unit. Its name must be unique across all of AWS. |
| **Object** | One file stored in S3, plus some information about it. |
| **Key** | The full name of an object, e.g. `photos/2026/cake.jpg`. |
| **Prefix** | The "folder" part of a key, e.g. `photos/2026/`. S3 doesn't really have folders – it just uses names that look like them. |
| **Storage class** | A price-and-speed level. Files you use often go in Standard; files you rarely touch can go in cheaper classes. |
| **Versioning** | A setting that keeps old copies of a file when you change or delete it. Like "version history" in Google Docs. |
| **Bucket policy** | A set of rules (written in JSON, a simple text format) saying who can do what with the bucket. |
| **Block Public Access** | A safety switch that stops anything in the bucket from being made public. It's on by default. |
| **Lifecycle rule** | An automatic rule, e.g. "move files to cheaper storage after 90 days, delete them after 1 year". |

## How it works (step by step)

1. You create a **bucket** in a Region you choose (for example, London `eu-west-2`).
2. You **upload** a file. S3 stores it as an **object** with a **key** (its name).
3. S3 automatically keeps copies of it across at least three Availability Zones (most storage classes).
4. By default, the bucket is **private** – only people and services you allow can read it.
5. When someone needs the file, they **request** it using its key. S3 checks their permissions, then sends it back.
6. You can add extras: versioning to keep old copies, lifecycle rules to move old files somewhere cheaper, and encryption (which S3 turns on for all new objects by default).

## When to use it

- Storing backups, documents, images and videos.
- Hosting a **static website** (a site made only of HTML, CSS, JavaScript and images – no server code).
- Keeping log files from other AWS services.
- Building a **data lake** (one big store of raw data for analysis) – see [Athena](../analytics/athena.md).
- Sharing files with an app or with other AWS services like [Lambda](../compute/lambda.md).

## When NOT to use it (and what to use instead)

- **You need a hard drive for a server's operating system.** S3 isn't a disk. → Use [EBS](ebs.md).
- **Many servers need to open and edit the same files at the same time, like a network drive.** → Use [EFS](efs.md) (Linux) or [FSx](fsx.md) (Windows).
- **You need a database you can search and update row by row.** → Use [RDS](../databases/rds.md) or [DynamoDB](../databases/dynamodb.md).
- **You're keeping files for years and almost never need them.** S3 still works, but choose a Glacier storage class to pay much less. → See [S3 Glacier](s3-glacier.md).

## Real-world example

**Scenario:** Sam runs a small online bakery. Customers upload photos of cakes they want copied, and Sam's website shows photos of every cake on the menu.

**The problem:** The photos are stored on the same small server as the website. The disk keeps filling up, the site slows down, and last month the server crashed and Sam nearly lost every photo.

**How S3 helps:** Sam moves all the photos into an S3 bucket. The website now loads images straight from S3 (through [CloudFront](../networking/cloudfront.md) for speed). Customer uploads go into a separate private folder. Versioning is turned on, so a deleted photo can be brought back. A lifecycle rule moves customer photos older than a year to a cheaper storage class.

**What it looks like:**

```
 Customer's browser
        │
        ▼
 ┌──────────────┐        ┌───────────────────────────────┐
 │  CloudFront  │ ─────► │  S3 bucket: sams-bakery-photos│
 │ (fast copies │        │   menu/      ← public via CDN │
 │  near users) │        │   uploads/   ← private        │
 └──────────────┘        └───────────────────────────────┘
                                   │ after 365 days
                                   ▼
                          Cheaper storage class
```

## Try it yourself

> ⚠️ **Cost warning:** S3 is included in the AWS Free Tier for new accounts, within limits (check the current [Free Tier page](https://aws.amazon.com/free/)). You pay for the amount stored, the number of requests, and data sent out to the internet. Storing a few small test files costs very little, but **always do the clean-up steps at the end.**

**Before you start:** An AWS account with MFA turned on (see [START-HERE.md](../../START-HERE.md)).

### Option A – Using the AWS Console (clicking in the website)

1. Sign in to the AWS Console.
2. Check the Region at the top right. Choose **Europe (London) eu-west-2**.
3. In the search bar, type **S3** and open it.
4. Click **Create bucket**.
5. Leave **Bucket type** as **General purpose**.
6. Enter a **bucket name**, e.g. `my-example-bucket-` followed by your initials and some numbers. (It must be unique across all of AWS, use only lowercase letters, numbers, dots and hyphens.)
7. Leave **Block all public access** ticked. This keeps your bucket private.
8. Under **Bucket Versioning**, choose **Enable**.
9. Leave the other settings as they are and click **Create bucket**.
10. Click your new bucket's name to open it.
11. Click **Upload** → **Add files**, choose a small file from your computer (e.g. a text file), then click **Upload**.
12. Click **Close**, then click the file's name to see its details – size, storage class and its **S3 URI** (address).

### Option B – Using the AWS CLI (typing commands)

```bash
# Make a new bucket in the London Region (change the name to something unique)
aws s3 mb s3://my-example-bucket-12345 --region eu-west-2

# Turn on versioning so old copies of files are kept
aws s3api put-bucket-versioning \
  --bucket my-example-bucket-12345 \
  --versioning-configuration Status=Enabled

# Create a small test file on your computer
echo "Hello from S3" > hello.txt

# Upload the file into the bucket
aws s3 cp hello.txt s3://my-example-bucket-12345/hello.txt

# List what's in the bucket
aws s3 ls s3://my-example-bucket-12345/

# Download the file again, saving it under a new name
aws s3 cp s3://my-example-bucket-12345/hello.txt hello-copy.txt
```

### Option C – Using Terraform (infrastructure as code)

Written for Terraform 1.x and the AWS provider `~> 6.0`.

```hcl
# Tell Terraform to use the AWS provider, version 6.x
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

# Work in the London Region
provider "aws" {
  region = "eu-west-2"
}

# Create the bucket (change the name to something unique)
resource "aws_s3_bucket" "example" {
  bucket = "my-example-bucket-12345"
}

# Make sure nothing in the bucket can ever be made public
resource "aws_s3_bucket_public_access_block" "example" {
  bucket                  = aws_s3_bucket.example.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

# Keep old versions of files when they are changed or deleted
resource "aws_s3_bucket_versioning" "example" {
  bucket = aws_s3_bucket.example.id
  versioning_configuration {
    status = "Enabled"
  }
}
```

Run `terraform init`, then `terraform plan` to preview, then `terraform apply` to build it.

### Clean up (delete what you made)

A bucket must be empty before you can delete it. With versioning on, "empty" includes old versions.

**Console:**
1. Open S3 and tick your bucket.
2. Click **Empty**, type `permanently delete`, and confirm. (This removes all files *and* old versions.)
3. Tick the bucket again, click **Delete**, type the bucket name, and confirm.

**CLI:** the quickest way is the Console's **Empty** button above, then:
```bash
# Delete the now-empty bucket
aws s3 rb s3://my-example-bucket-12345
```

**Terraform:** empty the bucket in the Console first, then run `terraform destroy`.

Finally, check the S3 page shows no test buckets left.

## How much does it cost?

S3 charges you for:
- **Storage** – per GB, per month. Cheaper storage classes cost less to store but more to read back.
- **Requests** – a tiny charge per upload, download or list request.
- **Data transfer out** – sending data from S3 to the internet. Uploading data *in* is free.
- **Extras** – e.g. replication to another Region, or some management features.

Official pricing: <https://aws.amazon.com/s3/pricing/>

## Security tips

- **Keep Block Public Access on** unless you truly need public files. For a public website, serve files through [CloudFront](../networking/cloudfront.md) and keep the bucket itself private.
- **Use least privilege** in IAM and bucket policies – give access to one bucket (or one prefix), not `s3:*` on everything.
- **Encryption at rest is on by default** for new objects. Use [KMS](../security-identity-compliance/kms.md) keys if you need more control over who can decrypt.
- **Turn on versioning** for important data, so a mistake or ransomware can be undone.
- **Never upload secrets** (passwords, access keys) to a bucket "just for now".

## Common mistakes

- **Making a bucket public by accident** – data leaks have happened this way. Leave Block Public Access on.
- **Forgetting that bucket names are global** – `test` and `backup` were taken years ago. Add something unique.
- **Leaving old versions behind** – with versioning on, deleted files still cost money until old versions are removed. Use a lifecycle rule.
- **Looking in the wrong Region** – the S3 list shows all buckets, but each bucket lives in one Region.

## Works well with

- [CloudFront](../networking/cloudfront.md) – delivers S3 files quickly to users worldwide.
- [Lambda](../compute/lambda.md) – runs code automatically when a file is uploaded.
- [S3 Glacier](s3-glacier.md) – cheaper storage classes for files you rarely need.
- [Athena](../analytics/athena.md) – runs SQL queries on files stored in S3.
- [IAM](../security-identity-compliance/iam.md) – controls who can reach your buckets.

## Quick check (test yourself)

1. What is the difference between a bucket and an object?
   <details><summary>Answer</summary>A bucket is the container (the storage unit). An object is one file stored inside it.</details>
2. You need a disk to install an operating system on an EC2 server. Should you use S3?
   <details><summary>Answer</summary>No. S3 is object storage, not a disk. Use EBS.</details>
3. Why might deleting files from a versioned bucket not lower your bill?
   <details><summary>Answer</summary>Because S3 keeps the old versions, and you still pay to store them. Remove old versions, or add a lifecycle rule to expire them.</details>
